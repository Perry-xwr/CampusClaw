# MCP 与工具调用

MCP（Model Context Protocol）是一种让 AI 应用以统一方式发现并调用外部工具的协议。典型结构包含 Host、Client 和 Server：Host 是面向用户的 AI 应用；Client 代表 Host 与某个 MCP Server 通信；Server 则声明可用工具并执行具体操作。工具可以连接业务数据或执行受控计算，但调用边界、身份验证和权限仍需由应用系统负责。

一个简单的工具调用过程通常从建立协议会话开始。Client 向 Server 发送 `initialize`，声明协议版本和客户端能力；Server 返回自身信息与协商结果。随后 Client 调用 `tools/list` 获取工具名称、用途说明和输入 JSON Schema。Host 可以把这些工具描述提供给模型，由模型决定是否发起调用；真正执行时，Client 发送 `tools/call`，包含工具名称与结构化参数。Server 校验参数，运行工具，并以协议结果返回文本或结构化内容。

MCP 消息可以采用 JSON-RPC 2.0 的请求、响应和错误结构。请求包含版本标记、方法名、参数和配对用的 id；成功响应通过相同 id 关联请求，错误响应提供错误代码和说明。通知没有响应 id。协议层正确并不意味着工具天然可信：服务端仍需验证调用者、参数范围和资源权限，客户端也应限制允许连接的服务器地址，避免被诱导访问未授权的内部服务。

工具描述中的 JSON Schema 用于表达参数类型、必填字段和取值约束，例如单位转换工具可以要求数值、源单位和目标单位。Schema 有助于模型形成正确请求，但服务端必须再次校验，不能把模型输出当作可信输入。工具返回结果后，Host 可以把结果作为受限证据交给模型生成面向用户的解释。工具调用状态也应与最终回答分开记录，方便界面显示“正在调用”或“调用失败”，并由后端保存审计信息。

安全实现应遵循最小权限原则。服务端令牌只由后端配置和持有，不应下发到浏览器；调用时需检查用户角色、班级或资源范围；敏感写操作应有明确授权、次数或速率限制，并记录用户、会话、工具、结果状态及时间。断开服务器后，应清除可调用工具缓存或将服务标记为不可用，后续调用必须失败关闭，而不能回退到无鉴权请求。

MCP 与普通 HTTP API 的职责不同：API 往往直接面向具体业务页面，而 MCP 提供可发现、可组合的工具接口。即使工具经由 MCP 暴露，Host 仍需要决定哪些技能或应用可以绑定哪些工具，并在执行前根据真实 Token 对应的身份做权限检查。这样模型负责提出结构化调用意图，服务器负责验证和执行，应用再把结果与来源清楚地呈现给用户。
